## 检查方法

### 语法检查

对每个 `_jianpu.txt` 执行：

- `validate_jianpu_text()`：检查元数据、分页/分谱标记、拍号、调号、力度、演奏标记、连音组、和弦、音符/休止符 token。
- `_read_new_syntax()` + `_validate_jianpu_token()`：逐 token 复核行号、列号和 token 内容。
- `parse_jianpu_scores()`：执行完整编辑器解析，捕获解析异常和小节时值诊断。

### 对应检查

- `musicxml_path_to_scores(..., target_key="auto")` 读取 XML/MXL。
- `scores_to_jianpu_text()` 与现有文本逐字比对，确认文件确实是当前生成器的输出。
- XML 结构独立扫描：小节数、voice、backup/forward、原始 note/chord 数量。
- 将简谱文本重新解析并重新导出 MusicXML，比较音高集合、事件数量、时值、小节数量、还原号和演奏标记。

## 逐行语法审计

9 个文件的每一条物理行都被扫描。header 行（调号/拍号）和每一条小节行均能被当前 token 解析器接受；所有文件的语法诊断数和逐 token 错误数均为 0。

以下行不是“语法错误”，但会在完整编辑器解析时产生对应问题：

### 附点音符被误当小节编号

解析器会先执行 `_strip_leading_measure_label()`。因此下面这种合法的附点音符开头会被删掉：

```text
2. (s5 s4) h0 |
```

受影响行：

- `微信图片_20260628233854_154_922_jianpu.txt`：物理行 4、7、12、13、15；对应 XML 小节 2、5、10、11、13。
- `2-9...page_005_jianpu.txt`：物理行 17；对应 XML 小节 15。

共 6 行。前一个文件的源音符数为 175，编辑器重解析后为 170；后一个文件相应少 1 个音符。

### 空小节被静默跳过

生成文本保留了单独的 `|` 行，但 `parse_jianpu_score()` 遇到没有 event/text block 的小节时不创建 `Measure`。受影响源小节为：

- page_003：5、6、15、16、17（丢 5 个）
- page_006：7-12（丢 6 个）
- page_004：21-25、32、41-43（丢 9 个）
- page_007：5-7（丢 3 个）

共丢失 23 个小节位置。后续按 `measure_index` 建立的渲染映射、编辑器小节号和原谱小节号不能直接认为一一对应。

## 已确认的对应错误

### 1. 非 C 调显式还原号 `n` 的音高错误

例如文本中：

```text
1=Bb
4/4
n1 |
```

在 Bb 调中，`n1` 应表示 C natural。当前 `_parse_pitch()` 将 `n` 保存为 `accidental=0`，再按 Bb 调写回 MusicXML 时得到 B-flat：

```xml
<step>B</step>
<alter>-1</alter>
<accidental>flat</accidental>
```

同样的问题发生在 F 调的 `n4`（应为 B natural，却被解释为 B-flat）。本批次明确受影响的 token 数：

- page_003 Bb：59 个
- page_008 F：21 个
- `微信图片_20260628233900_157_922` Bb：14 个
- page_005 F：21 个

合计 115 个。C 调中的 `n` 不产生这个特定的调号偏移问题。

### 2. 多声部没有可逆的简谱表示

全部 9 个 XML 都包含至少两个 voice。当前代码在 XML 读取时保留 `event.voice`，但按 staff 切分，不按 voice 切分；简谱 writer 随后直接遍历 `measure.events`，没有输出 voice 标记。结果是多个独立声部被串行写入同一小节。

这解释了大量项目层面的超拍诊断；例如 XML 原始结构含 `backup`/多 voice，而输出文本只有一条线性 token 流。它不是语法错误，但不能作为“每个 XML 音符在简谱中保持同一声部/时间位置”的证明。

### 3. `staccatissimo` 被丢弃

XML 解析出的未知演奏标记 `staccatissimo` 共 12 次。当前 `event_mark_ids()` 只输出规范表中的标记，未知标记不会生成任何简谱 token；现有 `_jianpu.txt` 中没有对应的 `staccatissimo` 表达。

已知规范标记（如 `staccato`、`accent`、`fermata`、`tenuto`、`arpeggio`、`up-bow`、`down-bow`）的数量在 XML 与重解析文本之间一致；丢失集中在这个未收录标记。

### 4. tie 终点存在自动补全差异

文本解析器会在发现未显式写出的 tie stop 时传播上一音的 tie start。聚合计数出现以下差异：

- page_003：XML tie stop 16，文本 17
- 微信图片 154：XML 2，文本 4
- page_008：XML 1，文本 2
- page_007：XML 1，文本 3

这属于解析器的上下文补全，不是 token 语法错误；在多声部/不完整 OMR tie 边界中，不能直接视为原 XML 的精确保持。

## 最终判定

- **语法判定：通过。** 当前项目语法校验器对 9 个文本逐行逐 token 均没有报错。
- **生成一致性：通过。** 当前 checkout 的 MusicXML 解析器和简谱 writer 在 `target_key="auto"` 下可逐字重生成这 9 个文件。
- **编辑器语义对应：不通过。** 至少存在 115 个调号相关音高错误、6 个附点开头音符被吞、23 个空小节被吞、12 个演奏标记丢失，以及多声部串行化和 tie 自动补全差异。

因此，这批文件可以证明“当前生成器产出了合法的简谱文本”，不能证明“简谱编辑区解析后的音高、时值、声部、小节和演奏标记与 MusicXML 完全一致”。

### P0 — 三连音结构丢失（L14 / 2nd-m1）

XML 2nd-m1 是 **3:2 三连音**（F4, Fb4, D4 三个 eighth，`time-modification` 3:2，`tuplet start/stop`）。简谱 L14 = `s4. sb4. ^> s2.~ ^. ~2 h0 |` —— **没有 `$3:2;` 连音标记**，三个三连音成员被转成普通附点 16th。时值从「3 个三连音 eighth = 1 拍」变成「3 个附点 16th = 1.125 拍」，连音结构和时值双双错误。

### P0 — slur 漏写 `)`（3 处，逐音确认）

| 简谱行 | XML 小节 | XML 实际 | 简谱输出 | 问题 |
|---|---|---|---|---|
| L8 | m6 | chord[A6,D6,B5] 有 `slur stop` | `h[6''+2''+7']` | 缺 `)`，`(h6''.` 开的 slur 永不闭合 |
| L7 | m5 | 2 个 `slur start`(number 1,2) | `(qb3'' (q2'' ... 2'')` | 只有 1 个 `)`，少 1 个闭合 |

这三处是转换器在处理和弦上的 slur_stop 时漏写 `)`，与「9/10 文件括号不配对」的批量统计吻合，且定位到具体小节。

### P1 — voice2 内容混入 voice1（3 处，逐音确认）

| 简谱行 | XML 小节 | 问题 |
|---|---|---|
| L3 | m1 | voice2 全休止 `w0` 被塞进 voice1 的 `$6:4;$` 连音组内（`w0.$`），voice2 休止不是连音成员 |

### P1 — 畸形长延音休止（L8）

XML m6 voice2 有一个 12 拍的多小节休止（`<rest measure="yes"/>` duration=288，跨 m6-m8）。简谱把它展平成 `0-----------`（0 + 11 个 `-` = 12 拍），全堆在 L8 一行。多小节休止应拆成多个 `w0` 或用多小节休止记号，不应一行堆 11 个延音号。

### P1 — measure rest 展平（L10）

XML m8 是 `<rest measure="yes"/>`（全小节休止，4 拍）。简谱 L10 = `h0 h0`（两个 half rest = 2+2=4 拍）。全休止应输出 `w0`，不应拆成两个 `h0`。

### P1 — Audiveris 输入数据问题（L21 / 2nd-m8）

XML 2nd-m8 里 Audiveris **重复了 D4-A4 两组音符**（同一 `id`，中间 `<backup>12</backup>` 回退），每组都带 `slur start` 但无 `slur stop`。简谱 L21 忠实产出了 `(s2 sn6 (s2 sn6 …` 两个 `(`，再加后续共 5 个 `(` 只 2 个 `)`，净余 3 个未闭合跨到 L22。根因是输入数据本身重复+缺 slur stop，但转换器没有容错处理。

### P2 — 32nd 前缀 `d` + 降号 `b` 粘连

大量 32th 降号音符产出 `db7'`、`db3'`、`db7` 等。`d`(32nd 前缀) + `b`(降号) 粘连成 `db`，与 64th `dd` 等前缀视觉混淆，可读性差。

### 确认正确的部分（逐音核对无误）

以下小节逐音核对全部正确：L12/m11、L15/2nd-m2、L17/2nd-m4、L18/2nd-m5、L20/2nd-m7（32nd 串音高全对）、L22/2nd-m9（fermata/staccato/跨行 slur 闭合全对）。

### P1 — slur 嵌套（项目规定 slur 不能嵌套，3 处）

| 简谱行 | XML 小节 | 简谱 | 问题 |

XML 用 `slur number="1"/"2"/"4"/"5"` 区分多条并行 slur，简谱只有 `(` `)` 一种标记，多条 slur 叠加就嵌套。

### P1 — 6/8 拍号变化不一致（m21）

m11 的 `<time>6/8` 在简谱 L13 有 `6/8` 标记（✓），但 m21 的 `<time>6/8` 在简谱 L23 **无标记**。同一类拍号变化，一个跟了一个没跟。
