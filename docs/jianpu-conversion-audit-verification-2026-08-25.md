## 4. XML -> 简谱对应

### 重跑确定性

对 10 个 XML/MXL 使用当前代码的 `musicxml_path_to_scores(..., target_key="auto")` 和 `scores_to_jianpu_text()`，在 `PYTHONHASHSEED=1/2/3` 三个独立进程下，10/10 哈希稳定且与存储文本逐字一致。

### 调号

首个 XML `<key>` 分别为：page_002=1(G)、page_003=-2(Bb)、page_005/page_008=-1(F)、微信图2=-2(Bb)。page_001、page_004、page_006、page_007 和微信图1没有任何 `<key>`，共 5 个，auto 回退 C；这是已确认的风险，但实际曲调是否不是 C 需要原谱或图片才能判定。

### 显式还原号 `n`

当前 `_parse_pitch()` 将 `n` 存成 `accidental=0`，没有抵消调号。非 C 调中重新导出会变成带调号的降音。明确受影响的 token：page_003 Bb 59、page_008 F 21、page_002 G 43、微信图2 Bb 14、page_005 F 21，合计 **158 个**。例如 Bb 调 `n1` 重新导出为 B-flat，而不是 C natural。

### 多声部不可逆

10 个 XML 都有至少两个 voice。当前代码保留 `event.voice`，但只按 staff 切分；writer 在 [jianpu_text.py](/D:/CODE/MyProjects/score_trans/backend/score_trans/domain/write/jianpu_text.py:167) 线性遍历 `measure.events`，简谱文本没有 voice 标记。多个声部被串进同一条时值线，导致大量超拍/少拍和结构错位。
