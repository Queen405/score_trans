# 小节出版布局优化实施与验收

> 本文记录 publication-34 的历史结果。跨系统列对齐与页底留白已在 publication-35 修正，见[后续修正与验收](column-alignment-page-fill-2026-11-09.md)。

日期：2026-11-09。引擎：`publication-34`。本轮根据已确认方案实现，所有 Python 命令使用 Bash 和项目 `.venv/Scripts/python.exe`。

## 最终行为

- 默认按拍组断开减时线，同拍组内部继续连接；常规拍号、3/8、复拍子、混合拍子分别处理。导入的 5/8、7/8 有明确连线分组时保留；无明确分组时使用确定性默认。
- 每行优先排所选的 3/4/5 小节，小节宽度按内容分配。同一系统的各声部共享小节边界与时间位置，不再要求上下系统使用相同的等宽列网格。
- 自然宽度不足时先压缩弹性空白；只有硬性最小宽度仍无法容纳，才减少该行小节数。单小节独占一行仍放不下时报告具体小节，不静默缩字或重叠绘制。
- 普通长音、普通休止和长和弦从首拍开始。增时线进入后续时间位置；和弦共享增时线位于音符叠排的中部。
- 和弦保持 90%×68% 的字形配置和最低音基线；附点逐层绘制，同音延音线逐层连接相应音高，支持两端和弦层数变化。
- 单声部和多声部使用同一套小节测量及定位，不再因固定/自动模式切换而调用不同的间距算法。

## 实现要点

`services/render/engraving/spacing.py` 保存小节时间列、实际部件边界和两种位置序列：满足所有硬约束的最紧序列，以及加入时值弹簧后的自然序列。两者之间的插值只收紧弹性空白；更宽的布局按非负时间权重分配余量。连音组的约束和拉伸权重同时保持时值比例。

每条声线和每段歌词分别提出碰撞约束，不能把不同高度的左右极值直接合成一个大横向盒子。相同时刻只有一个共同 x，交换声部输入顺序不改变结果。

`geometry.py` 与实际绘制共用和弦附点、共享增时线和节奏线的几何参数。字号变化时，线宽、层距、附点位置和增时线长度同步缩放，已覆盖 70%、100%、140% 三档。

旧版事件位置、拍界再分配、拥挤压缩等重复算法已删除。页面分页、乐器分组、来源定位和播放时刻继续接入原有流程。

## 实图检查后继续修正的问题

1. **小节号与演奏记号重叠**：第 6 页发现一处真实重叠。小节号改用系统内统一的预留位置，位于相关符号包络上方，并将该位置计入分页测量。
2. **短休止符前后的大空洞**：初版仍只对有音高的短音对进行压缩，导致八分休止符到下一个和弦的间距明显偏大。最终改为按共同时间间隔处理，音符和休止符不再受到不同的压缩待遇。
3. **连音组拉伸失真**：其他声部插入额外时间列后，连音组不仅需要最小位置等比例，还需要拉伸权重等比例；已增加对应回归。
4. **误报与真实碰撞混在一起**：事件包围盒含有数字、记号之间的空白。现在事件间按实际部件判断碰撞；共享减时线与空白容器相交不再被当成真实符号碰撞。另有正反用例确保实际重叠仍然报错。
