# 《we are the world》双声部简谱布局诊断

按用户提供的原文、每行 5 小节、当前默认布局复现。使用 Bash 和项目 `.venv/Scripts/python.exe`，没有修改输入音符、用户设置或应用数据库。本次为定位问题，尚未修改渲染算法。

## 输入与实际输出

- 两个 Piano 声部，每声部 35 小节；来源第 1 页为 14 小节，第 2 页为 21 小节。
- 语法及小节时值检查通过，全部小节符合输入的 4/4。
- 真实 `RenderActions.render_batch_a4` 路径输出 3 页，系统数为 **1、3、3**。Electron Chromium 完整页面截图确认了同样的结果。
- 首页面末音乐内容至纸边约 **184.87 mm**，第二、三页约 **7.45 / 7.24 mm**。这不是普通页底边距造成的。
- 两个 Piano 声部已经自动分组；大括号过长来自内部几何尺寸被撑高，并非缺少分组识别。

## 首要缺陷：短时值低音和弦的坐标与避碰反馈

同一组音高、同一字号下，当前引擎测得的符号包围盒高度如下。布局单位来自引擎虚拟页面坐标，普通音符字号为 30。

| 输入 | 高度 | 三个数字的纵向基线 |
| --- | ---: | --- |
| `[7,+5,+2,]` | 85.11 | -60.95、-30.78、0 |
| `q[7,+5,+2,]` | 409.33 | -180.43、-119.27、0 |
| `s[7,+5,+2,]` | 443.77 | -195.19、-129.11、0 |

问题位于 `backend/score_trans/services/render/engraving/geometry.py` 的 `pitch_layouts` 和 `_low_octave_first_center`：

1. `pitch_layouts.build` 的数字及低音点盒子采用整组事件的相对坐标。
2. 对短时值音符，低音点使用公共减时线的底部 `base`，但随后又执行 `base - row_y`。和弦上层的 `row_y` 为负数，这会把上层音的低音点推到更低的位置。
3. 层间避碰又以这些已经错误的低音点为边界，把上面的数字推高；之后重新构建低音点位置时再次受更负的 `row_y` 影响。
4. 结果是数字向上分裂、低音点漂到下方空白区。普通四分和弦与短时值和弦的上层数字也无法形成视觉稳定的行列。

这条链解释了第 4 小节突然悬空的 7、5、散落的低音点，以及倾斜跨接的逐音延音线。

## 派生问题：错误盒子撑大了谱表间隔与小节线

`_measure_bar_offsets` 把全部低音点纳入小节线长度；`_part_vertical_envelope`、`_compact_fixed_parts` 又用这些盒子计算上下谱表之间的安全距离。

第一系统的上下谱表原点距离被算到 **300.53 单位**。其余系统也达到约 **271–289 单位**。因此：

- 小节竖线被拉得很长；
- 钢琴两行之间出现大块无意义的空白；
- 大括号随谱表高度一起拉长；
- 系统容纳数量下降，进一步增加输出页数。

这几个现象有共同的几何根因。直接减小声部间距参数会保留漂浮的符号，甚至造成碰撞。

## 独立缺陷：分页评分偏爱留下孤立的首页

`renderer.py::_paginate_fixed` 对少于 3 个系统的页面统一增加 500 分惩罚，1 个系统和 2 个系统的额外惩罚相同。对这份原文枚举可行的 3 页方案，得到：

| 每页系统数 | 当前评分，越小越优先 |
| --- | ---: |
| 1 / 3 / 3 | 975.73 |
| 2 / 2 / 3 | 1311.66 |
| 2 / 3 / 2 | 1322.29 |
| 3 / 2 / 2 | 1338.92 |

后面三种方案均能安全放下。当前评分却把“前两页各放 2 个系统”罚了两次，最终选择首页只放一个系统。这是首页留白过大的第二个原因；修复符号几何后仍需独立验证分页行为。

## 另一个明确缺陷：首个声部前的标题被忽略

用户原文的 `title=we are the world` 位于第一个 `@page` 后、首个 `@part` 前。`parse_jianpu_parts` 检查这段前导文本允许包含配置，却没有将其中的标题应用到解析结果。

直接解析得到的 4 个来源片段 `score.title` 均为 `None`；通过真实批量请求路径时显示后备标题“简谱”。此前移除请求层强制标题覆盖的修复没有覆盖这个不同的解析缺陷。

## 国标核对与修复边界

已视觉核对仓库中 `docs/GB_T_46845-2025_音乐曲谱出版_简谱_通用规范.pdf`：

- 5.10.3 c、d：并列二、三声部的减时线**可**合用。合用属于允许的略记方式。
- 6.2.4.3：低音点与减时线同时使用时，低音点应位于减时线下方。
- 5.10.3 f：并列声部同时值休止符可合记，用普通字体。因此普通休止符与扁体和弦字形存在大小差异，不能据此把休止符随意缩扁。

修复应同时明确每个音的局部坐标、八度点归属，以及独立/合用减时线的绘制与测量策略。不能只把浮动低音点上移或直接隐藏。现有 `test_chord_low_octave_dots_stay_below_shared_duration_lines` 只检查点是否位于公共减时线下方，没有限制它与音符的距离，也没有检测改变时值引起的异常高度膨胀，因而未能捕获本例。

## 建议修复顺序与验收

1. 重做短时值低音和弦附件的坐标计算，使层间避碰基于最终实际绘制的局部几何；验证八度点、减时线、逐音延音线的归属关系。
2. 用修正后的实际墨迹重新计算两手谱表间距、小节线及大括号，保持最低音基线与上下手共同时间列。
3. 修复分页评分对孤立页面的偏好，比较实际内容占用与页间均衡；固定每行 5 小节，系统数由真实内容决定。
4. 正式解析首个 `@part` 前的标题配置，保留编辑器 UTF-16 偏移和来源定位。
5. 将这份 35 小节原文加入视觉回归样例。除避碰外，增加同音高不同短时值的高度增长约束、八度点归属、首页占用、旧结果刷新及标题位置测试。
